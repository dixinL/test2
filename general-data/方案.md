# test2 / general-data 第一阶段：龙头股基础数据入库（baostock）

## Context

用户在 test2 复刻 test1 的"general-data → 分析"分层模式。目标：把 `test2/申万二级行业龙头_修正版.csv` 中 320 只龙头（31 个一级行业、130 个二级行业）2020-01-01 至今的行情与财报数据统一存入 SQLite，作为后续所有分析模块的唯一数据源。

数据源已实测选定 **baostock**（日K 18 字段内嵌 peTTM/pbMRQ/psTTM/pcfNcfTTM/tradestatus/isST，另含复权因子与季频财务接口；akshare 东财日线仅 12 字段无估值，乐咕接口已移除）。

用户决策：
- 复权口径：**存不复权原始价 + 复权因子表**（adjustflag=3），分析时现算前/后复权——历史行永不重写，与 test1"非必要不重写历史行"的幂等原则一致；前复权价因每次除权后全历史基准漂移、需整股重拉，已否决
- 建两张数据表：**每日数据表 + 财报数据表**（季频财务一并入库）
- 动态 ROE(TTM) 可由 PB/PE 现算，但毛利率等仍需财报表

## 表结构（leadersdb.init_schema）

1. **leaders** 维表（CSV 幂等导入，UPSERT）
   - PK `code`（6位代码，如 `000998`）；`exchange`（SZ/SH）、`name`、`sw1`、`sw2`、`leader_type`、`moat`、`margin_2023/2024/2025`、`roe_2023/2024/2025`、`updated_at`

2. **daily** 日频表（主表）
   - PK `(code, trade_date)`
   - 行情（**不复权原始价**，adjustflag=3）：`open, high, low, close, preclose`
   - 量额：`volume, amount, turn, pct_chg`
   - 状态：`tradestatus`（停牌=0）、`is_st`
   - 估值：`pe_ttm, pb_mrq, ps_ttm, pcf_ncf_ttm`

3. **adjust_factor** 复权因子表
   - PK `(code, divid_operate_date)`；`fore_factor, back_factor, adjust_factor`
   - 用途：现算前/后复权价的基础。baostock 口径：`close_qfq = close × fore_factor`（前复权，基准=最新交易日）；`close_hfq = close × back_factor`（后复权，基准=上市日）。因子表随 refresh 增量维护，除权后无需重写任何 daily 历史行

4. **financial** 财报表（UPSERT 覆盖，财报数据可能重述）
   - PK `(code, year, quarter)`（quarter∈1~4：一季报/中报/三季报/年报）
   - `pub_date, roe_avg, gp_margin(销售毛利率), np_margin, net_profit, eps_ttm, yoy_ni(净利润同比), yoy_asset, liability_to_asset(资产负债率)`
   - 来源：baostock `query_profit_data` + `query_growth_data` + `query_balance_data`（每季 3 次调用合并一行）

## 文件职责

### leadersdb.py（访问层）

### bsfetch.py（抓取层）
- 代码转换：CSV `sz000998` → baostock `sz.000998`（`to_bs_code()`）
- `bs_login()/bs_logout()` 上下文封装；重试 3 次 + 退避（对齐 test1 swfetch 的 FETCH_MAX_RETRY 模式）
- `fetch_daily(code, start, end)`：`query_history_k_data_plus`，字段含估值/状态全套，**adjustflag='3'（不复权）**
- `fetch_adjust_factor(code)`
- `fetch_financial(code, year, quarter)`：profit/growth/balance 三接口合并为一行 dict
- 校验：OHLC 数值化、空行过滤、停牌行保留（tradestatus 区分）

### leadersdb.py 附加（复权现算）
- `get_adjust_factors(code) -> list[(date, fore, back, adj)]`：升序因子序列
- 复权换算规则（baostock 口径）：对 trade_date 晚于最近一次除权除息日 divid_operate_date 的因子生效——`qfq_price = price × fore_factor`（同日以 factor=1 起算向后追溯），`hfq_price = price × back_factor`。以纯函数实现，供各分析模块直接调用

### refresh.py（刷新入口，全部幂等）
```
用法:
  python refresh.py                 # 日常增量（daily 增量 + 财报最新季 + 除权检测）
  python refresh.py --full          # 首灌：daily 从 2020-01-01 起，financial 从 2020Q1 起
  python refresh.py --financial-since 2022Q1   # 财报回填起点
  python refresh.py --no-financial  # 跳过财报（行情快速刷新）
  python refresh.py --stats         # 只打印覆盖情况
```
流程：
1. CSV → leaders 维表 upsert（每次跑，幂等；CSV 更新后自动同步）
2. **逐股 daily 增量**：从库内 max_date+1 拉到今天（不复权），INSERT OR IGNORE
3. **adjust_factor 增量**：拉全量因子并 INSERT OR IGNORE（除权只影响因子表，daily 历史行零重写）
4. **财报增量**：从库内 max(year,quarter) 起拉到当前报告期；首灌 `--full` 时 2020Q1 起
5. 每步打印"成功/失败/新增行数"，重复运行新增 0 行即数据就绪

## 性能预估（实测口径）

- daily 首灌：320 股 × 1 次调用 ≈ 5~10 分钟
- daily 日常增量：320 次 ≈ 2~3 分钟
- financial 首灌：320 股 × 27 季 × 3 接口 ≈ 2.6 万次调用，**约 1~2 小时，一次性本地跑**（baostock 单连接串行）；日常增量只需最新报告期 ≈ 千次内
- baostock 日线 T 日 17:30 后更新，CI 若在收盘后立刻跑会少一天数据，属预期行为
